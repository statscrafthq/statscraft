# The window

```
statscraft-gui survey.sav job.sps     open a data file and a syntax file
```

`statscraft-gui` is a desktop window over the same engine, in four tabs. Files dropped on the window from the file manager open too: a .sav or .zsav file as data, a .sps file in the syntax editor (one of each at a time; the status bar names the files left out).

- **Data**: the cases in a grid that draws only the visible cells, with value labels on or off. Each column draws its values and labels with the variable's alignment (numbers to the right and strings to the left when the file sets none). While `FILTER BY` is in force, the row number of every case the filter leaves out has a diagonal stroke through it; the case stays in the grid. Double-click a cell or press Enter to change it; Enter commits, Escape cancels. Arrows, Page Up and Down, Home and End move the selection, Ctrl with an arrow goes to the first or last row or column, Ctrl+Home and Ctrl+End to the first and last cell, and Tab and Shift+Tab move to the next and previous cell, committing an edit on the way. Shift with those keys, or Shift+click, extends the selection to a block; a click on a row number or a column name selects the whole case or variable (Shift+click a range, Ctrl+click one more or one less). Ctrl+C copies the selection as tab-separated text with the variable names as the first line, for a spreadsheet or a text editor; one cell copies as its text alone, and more than two million cells are not copied. Delete asks to delete the variables whose columns are selected. A column is as wide as the variable's display width (the width a .sav file keeps for each variable); drag the border at the right of its name to change it, which runs `VARIABLE WIDTH var (n).`, so the width is saved with the data.
- **Variables**: one row per variable with name, type, format, width, decimals, label, value labels, missing values, columns (the display width, as wide as the Data View shows it), alignment, measure and role. Double-click to change a field. The type (Numeric, Date or String) and the format open a small dialog that offers only formats there are, numbers (plain, comma, dot, dollar, percent, scientific, leading zeros), dates and times, and strings, with the width and decimals as numbers within that format's limits; it runs `FORMATS`, or `ALTER TYPE` for a new type or string width (a new type drops value labels and missing values, and the dialog says so). Value labels open an editor with one row per code and label to change, add and remove, which runs `VALUE LABELS` with the whole set; or Paste many, a text area for many lines of a code and a label with a tab, semicolon, equals sign or comma between (the first of these the text holds), which either updates (`ADD VALUE LABELS`: new codes added, the labels of codes there are changed) or replaces the whole set (`VALUE LABELS`). Missing values open an editor for up to three values, or for numbers a range (LO and HI for the lowest and highest value) and one value more, which runs `MISSING VALUES`. When the variable's row is one of several selected rows, both editors can give the same labels or missing values to the other selected variables of its type. Columns runs `VARIABLE WIDTH`, alignment `VARIABLE ALIGNMENT` and role `VARIABLE ROLE`, chosen from a list like the measure. A variable without an alignment or role in the file shows numbers to the right, strings to the left and the role Input. The keys, selection and Ctrl+C work as in the Data View, Enter changes the cell at the cursor; Delete deletes the variables whose row numbers are selected, with `DELETE VARIABLES`, after a question (Edit, Undo last change brings them back). Drag a column border to resize it; these widths are a window setting.

Ctrl+F in the Data View or the Variable View opens a find bar: typing goes to the first variable whose name or label holds the text (any case), Enter or F3 to the next one, Escape closes the bar. The Variable View goes to the variable's row, the Data View to its column.

A right click opens a menu over what it lands on. On a column name (or the selected columns, when it lands inside them) the menu sorts the cases ascending or descending by them (`SORT CASES`), runs Frequencies, Descriptives (numeric variables only) or Variable information (`DISPLAY DICTIONARY`) at once, opens Frequencies, Descriptives, Explore, Crosstabs (two variables go to rows and columns) or Custom Tables (scale variables to the means) with the variables filled in, sets the measure, renames the variable, shows its row in the Variable View, opens Recode, inserts a numeric variable `new_1` before it (`NUMERIC` and `MATCH FILES /KEEP`, with `WEIGHT BY` again when a weight is on), copies, or deletes. On a cell it copies, edits or clears the value, keeps only the cases with the same value with a filter (`COMPUTE filter_$ = (age = 49).`, `VARIABLE LABELS` and `FILTER BY`, on the stored value rather than the rounded one shown, `VALUE(x) = 99` for a user-missing value, `SYSMIS(x)` for an empty cell; a variable `filter_$` of other data is never overwritten, the next free `filter_$_2` is used), stops filtering, opens Select Cases to delete the other cases, or sorts by the variable. On a row number it copies or deletes the case (`COMPUTE #row = #row + 1.` and `SELECT IF #row <> 12.`). In the Variable View the menu on row numbers is the one of the columns, with Show in Data View, and on a cell it starts with Edit for that field. The top of a menu names what it acts on and the split, filter and weight in force. Items that run syntax wait while a run is going on, and the analyses and sorting are off without cases. Every item runs syntax like any other run, so it shows in the log and Ctrl+Z takes a change back. Deleting variables or a case, sorting while a split is on (sorting ends the split) and Frequencies of more than 100 variables first show the question and the syntax; only a click on the button runs it, Escape cancels.
- **Syntax**: an editor with line numbers and colours for command names, subcommands, keywords, strings, numbers, comments, macro words (`!name` and the words of the macro language) and the period that ends a command. A macro defined with DEFINE in the editor text or in an earlier run of the session is coloured as a macro where it is called, also where a command would stand. Run all, or Run selection (Ctrl+Enter) for the commands on the selected lines; on a line with no command (the empty line under a command just typed) it runs the command above. Errors show at their line and column. While typing, a list offers what fits at the cursor: command names at the start of a command (abbreviations such as FRE or VAL LAB find the full name), subcommands after `/`, keywords of the command, the variables of the open data with their labels, function names where an expression goes, the macros defined with DEFINE in the text or the session (where a command goes and inside commands), and after `!` the words of the macro language. Ctrl+Space opens the list at any point; arrows choose, Enter or Tab puts the choice in, Escape closes it. A command in the list, or a command name under the mouse, shows its summary and syntax; F1 opens the full help of the command at the cursor in a small window.
- **Output**: every result table with its multi-level header, beside a navigator that groups the tables by run and command (a run folds away with a click on it). Columns are as wide as their numbers, which align right; long row labels and column headers wrap between words, and a row label repeated under the same outer labels is shown once beside all its rows. The caption and notes follow each table. A run selects nothing, so its tables show without a frame; click a table, or its name in the navigator, to select it (Ctrl+click for more, Ctrl+A for all), and click it again, press Escape or click beside the tables to clear the selection; the syntax of its command shows under the navigator, exactly as it ran, with Copy, Paste (into the syntax editor) and Run again, and pointing at a command in the navigator shows it too; then Copy (Ctrl+C) puts it on the clipboard with its layout for a word processor or spreadsheet and as plain text beside it, Copy as text gives tab-separated text, Delete removes it, and Export selection saves only the selected tables as a web page or an Excel workbook. Right-click a table for the same. Each table is measured once and only the tables in view are drawn, so hundreds of tables scroll smoothly.

File, Export output as HTML saves the whole output as one web page; File, Export output as Excel saves it as a workbook, with One sheet per table or All tables on one sheet, laid out as `--xlsx` does.

The menus have dialogs that build syntax:

- **Data**: Define Multiple Response Sets (dichotomy or category sets, counted value, labels, deleting sets), Sort Cases, Split File (groups compared in the same tables or in tables of their own, sorting the cases first, or off), Select Cases (a filter that leaves the other cases out of analyses: `COMPUTE filter_$ = (condition).` and `FILTER BY filter_$.`; SELECT IF, which deletes them; or all cases again with `FILTER OFF.` and `USE ALL.`), Weight Cases, Aggregate (into every case, a new dataset of one case per group, or a file) and Merge Files with Add Cases and Add Variables (with keys, or a lookup table).

- **Transform**: Compute, Recode, Count Values within Cases, Rank Cases (every RANK function with new names or the default ones, ranks within groups, from the smallest or the largest value, ties, the proportion formula, user-missing values) and Automatic Recode (AUTORECODE into new variables, from the largest value, one scheme for all, blank strings as missing, a table of the values).

A dialog shows the syntax it builds: OK runs it, Paste puts it in the syntax editor. Options left at their defaults add nothing to the syntax. Warnings of a run appear under its command in the log, and the status bar says how many there were; a click there shows the log (from the Data or Variable View, in the Syntax view). Errors show in the status bar, whatever the view. At its right the status bar names the split, filter and weight in force, such as `Split by region (layered)`, `Filter: filter_$` and `Weight: weight`; a click on one opens Split File, Select Cases or Weight Cases.

Syntax is the only command layer: every change and every result in the window comes from syntax run by the engine, exactly as `statscraft run` runs it. Opening a file runs `GET FILE`, editing a cell runs `IF ($CASENUM = n) var = value.`, editing a label runs `VARIABLE LABELS`, and so on. The log under the Syntax and Output views (View, Log under Syntax and Output turns it off; the Data and Variable Views give the grid the whole height) lists every command with what it changed, and Copy syntax there gives a script that repeats the session. Macros defined by one Run (DEFINE, or INCLUDE of a macro library) stay defined for the later ones while the window is open, with the macro settings of SET.

View, Paper chooses how the Data and Variable grids and the output tables look: Always light (the default) keeps them dark text on a light sheet while menus, panels and dialogs follow the system's dark or light theme, as a spreadsheet or a document page does; Follow the system theme draws them in the system theme too. View, Syntax colours chooses the colours and background of the syntax editor from Statscraft Light (the default) and Dark, in the Statscraft colours, and ready-made editor themes: Catppuccin Latte and Mocha, One Dark, Solarized Light and Dark, GitHub Light and Dark.

Help, Documentation opens these pages online; Help, About shows the version, the license (MIT), links to the source code and the documentation, where the colour themes come from with their licenses, and the licenses of the fonts.

The window remembers its size and position, the folder of the last file dialog, the ten files opened or saved last (File, Recent files), the paper setting, the syntax colours, the Variable View's column widths and the update check setting in `statscraft/window.txt` in the user's config folder: `%APPDATA%` on Windows, `$XDG_CONFIG_HOME` or `~/.config` elsewhere.

Edit, Undo last change (Ctrl+Z outside a text field) puts back the dataset from before the last run that changed it, one step; the log marks that run as undone and Copy syntax leaves it out. Long lines in the syntax editor wrap at the window edge; View turns that off.

Opening a file and every run happen off the drawing thread: the status bar shows what is running and the window stays responsive. One run goes at a time; requests from the command line wait their turn.

## Updates

The window asks GitHub at most once a day, in the background and never holding up the start, whether a newer release is published. Checks are on by default and say nothing unless a newer version is out. Help, Check for updates automatically turns them on and off (the line `updates on` or `updates off` in `window.txt`), and Help, Check for updates checks at once and also says when there is nothing new.

When a newer release is out, a small bar under the menu says so, with a link to the release notes, **Update now** and **Later**. Later hides the bar until the next check. Update now downloads the package for this installation, checks it against the release's `SHA256SUMS` and then:

- installed with the Windows installer: closes the window, runs the new installer silently for the same per-user installation (same folder, file types and Start menu entry) and the installer opens the window again. Save your work first.
- installed from the tarball: replaces `statscraft` and `statscraft-gui` in its `bin` folder (each written next to the old one, then renamed over it) and offers **Restart now**.
- installed from the .deb: saves the package in `~/Downloads` and shows the one command that installs it, `sudo apt install ~/Downloads/statscraft_X_amd64.deb`, with a button that copies it. The window never runs sudo.
- built from source or copied elsewhere: there is no Update now; the bar says to install the new version the way this copy was installed.

The check is one request to the GitHub API with the User-Agent `statscraft/VERSION`; nothing about you or your data is sent. `statscraft update` does the same from the command line.

## Driving the window from the command line or an AI agent

While the window is open it is a live session named `gui`:

```
statscraft run -s gui -e "GET FILE='survey.sav'."         the window opens the file
statscraft run -s gui --json job.sps                      runs job.sps in the window
statscraft check -s gui -e "COMPUTE x = age / 10."       validates against the window's data
statscraft describe -s gui --json                        dictionary of the window's dataset
```

The window runs the syntax exactly as its own Run button does: the tables appear in Output, the commands in the log, and the data grid shows the result. The command line prints what it prints for a file session, with `"session": "gui"`; `saved` is true when the run changed the window's dataset (nothing is written to disk unless the syntax says SAVE). Relative paths in the syntax are read from the folder where `statscraft` was started, and the window stays in that folder.

So an AI agent with a shell can work in the open window: start `statscraft-gui`, then tell the agent to use `statscraft run -s gui --json` for every step and `statscraft help COMMAND` for the syntax. The person watching sees each table appear and can keep working in the window between the agent's runs.

How it connects: on start the window listens on a random TCP port of 127.0.0.1 and writes the address and a random token to `statscraft/gui.json` in `$XDG_RUNTIME_DIR` on Linux or `%LOCALAPPDATA%` on Windows (`~/.config` otherwise), readable only by the user. A request without the token is refused, and the command line sends the token only to a local address. When no window is open, `-s gui` fails with "no Statscraft window is running". With several windows open, the one started last answers.

The window brings its own fonts: Schibsted Grotesk for menus, dialogs, grids and output, with digits of equal width so numbers line up in columns, and JetBrains Mono for syntax. Both are under the SIL Open Font License. Characters they lack, such as Cyrillic in Schibsted Grotesk, come from system fonts (Segoe UI and Consolas on Windows, DejaVu, Noto or Liberation on Linux). Set `STATSCRAFT_FONT` or `STATSCRAFT_MONO_FONT` to a .ttf file to use another font first.
